Decision 2 of 8

Theme and skin model

Visual

Aquí separamos dos conceptos que suelen mezclarse. Un theme debería controlar condiciones de lectura y apariencia base —por ejemplo dark, light o high-contrast—, mientras que un skin expresa personalidad visual —paleta, superficies, bordes y tratamiento del producto—. La decisión debe permitir combinarlos sin multiplicar presets ni crear combinaciones no soportadas.

Dime: “Option B” · “Option A but [cambio]” · “more options”

Option A

Theme only

dark
Un solo eje de apariencia
Solo existe un selector de theme, con variantes como dark, light o high-contrast. Los cambios de personalidad visual se modelan como nuevas variantes del mismo eje. Es sencillo, pero mezcla accesibilidad y branding y hace crecer una lista de presets difícil de gobernar.

Funciona bien cuando

  • Solo habrá dark/light.
  • La personalización es mínima.

Vigilar

  • Dark + neon acaba siendo un preset monolítico.
  • Accesibilidad queda mezclada con estética.

Orthogonal theme + skin

resolved UIsupported pair
Mantener dos ejes explícitos: el theme define modo, contraste y preferencias de lectura; el skin define la identidad visual. `dark + default` será la combinación actual. El resolver valida combinaciones soportadas y aplica tokens, mientras que cada componente permanece ajeno a la selección. Es la opción más flexible sin perder gobernanza.

Funciona bien cuando

  • Accesibilidad y branding deben evolucionar por separado.
  • Habrá varios skins con pocos themes.
  • Se quiere evitar combinaciones imposibles.

Vigilar

  • Requiere una matriz de compatibilidad.
  • Hay que definir defaults y fallback.

Exponer únicamente combinaciones completas y predefinidas. El usuario elige “Default”, “Midnight” o “Paper” y el sistema no ofrece ejes independientes. Simplifica la UI y el testing, pero limita la evolución y hace que cada nueva combinación requiera un preset nuevo.

Funciona bien cuando

  • La lista de skins es pequeña y curada.
  • Se prioriza una selección muy simple.

Vigilar

  • Duplica definiciones entre presets.
  • Menos reutilizable para accesibilidad.

Option D

User-made themes

Build your own skin
Permitir que el usuario configure colores, radios, densidad y efectos libremente. Es potente para una comunidad avanzada, pero introduce combinaciones infinitas, problemas de contraste y una superficie de soporte mucho mayor. No encaja con la primera etapa de limpieza.

Funciona bien cuando

  • La personalización es un producto por sí mismo.
  • Hay validación visual automatizada.

Vigilar

  • Riesgo alto de accesibilidad rota.
  • Hace más difícil reproducir bugs.
